# Технічне завдання · ЛР № 3 · Варіант 2

Жуков Михайло Володимирович. y′ = -2y, y(0) = 3, x ∈ [0;2].
Еталон: y(x)=3 exp(-2x). Підстановка: y′=-6 exp(-2x)=-2y; y(0)=3.

## Вимоги

1. Ейлер, Хойн (явна трапеція) і класичний РК4; спільний інтерфейс Strategy.
2. Реєстр методів: додавання стратегії без редагування інтерфейсу.
3. Ручне введення f(x,y), x0, y0, xEnd, n; необов'язковий точний розв'язок.
4. Парсер арифметичних виразів без eval/new Function; скінченні значення;
   додатне ціле n ≤ 10000; нетривіальний інтервал.
5. 6 графіків для n=5/10/20: точний розв'язок з трьома методами і похибки.
6. Вузлові таблиці, max-похибка, кінцева похибка, час, CSV з UTF-8 BOM.
7. Відношення e(h)/e(h/2), порядок log2(ratio); додаткове уточнення для РК4.
8. Стійкість Ейлера: y′=-20y, y(0)=1 на [0;1], n=5/10/20.
9. Покрокова анімація, проміжні стадії РК4; відтворення, пауза, повзунок.
10. Автомасштаб X/Y за показаними даними, включно зі стадіями.
11. Бонус: Лотка–Вольтерра через векторний РК4, фазовий портрет та інваріант.
12. Прямий запуск index.html, тести Node.js, README, GitHub Actions workflow.

## Методологія

Розвиток Agile з ЛР № 2: ітерації з практиками XP - тести до реалізації
математичного ядра (TDD), регресійний набір, локальний тест порядку та CI.
Перший невдалий запуск збережено в results/tdd_initial.txt. Після реалізації
ті самі вимоги перевіряються повторно. Публікація й запуск GitHub Actions
потребують віддаленого репозиторію; наявність workflow не є доказом запуску CI.

## Критерії приймання

Усі 9 розрахунків варіанта завершуються, похибки спадають при уточненні.
Для малих h порядок наближається до 1/2/4. Контроль РК4 на n=40/80
має 14 < e40/e80 < 18; навмисно змінений коефіцієнт має провалювати перевірку.
Ейлер для тесту стійкості дає y(1)=-243, 1, 0 відповідно. Невірний ввід
не замінює останню коректну задачу. Усі графіки та CSV працюють без сервера.
